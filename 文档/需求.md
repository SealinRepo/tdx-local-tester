# 本地交易回测与看盘系统 — 功能需求

> 本文按当前产品功能整理，描述系统现有行为、接口、策略语义及限制。跨功能的长期约束见[项目规范](./项目规范.md)，策略 API 的参数和示例见[策略函数说明](../document/策略函数说明.md)。

## 1. 系统定位

为个人投资研究提供本地通达信行情查看、Python 策略管理和历史回测。应用在本机运行，行情从配置的通达信目录读取，回测结果保存在本地 JSON 文件。

主要能力：

- 回测：多标的策略回测、交易明细、绩效指标、净值图和历史结果管理。
- 看盘：本地日线 K 线、行情详情、均线及分时图。
- 策略工作区：脚本列表管理、Python 编辑器、代码检查、保存、运行和 API 帮助。
- 设置：配置并验证通达信数据目录。

## 2. 页面与通用交互

- 顶部导航在“回测”“看盘”“设置”页面之间切换。
- 顶部导航区域有固定/取消固定按钮；启用后页面滚动时固定在顶部。
- 日期输入默认使用本机日期：结束日期为今天，开始日期为一年前；看盘和回测使用相同默认区间。
- 用户操作、数据读取和策略运行中的错误应通过页面状态或提示明确显示。

## 3. 设置与本地数据

- 设置页允许填写并验证通达信安装目录；配置保存在项目根目录 `config.json`。
- 日线和 1/5 分钟分时行情由本地通达信数据读取组件提供；看盘数据不依赖远程行情接口。
- 股票代码/名称目录从通达信本地索引读取，按市场来源和代码段筛选沪深北普通 A 股，排除 B 股、基金、指数及债券；名称以“退市”“退”或“摘牌”开头的记录也排除。该索引没有统一可靠的上市状态字段，退市筛选仅能做到尽力过滤。
- 搜索结果同时显示代码和名称，可用于看盘选股；搜索无结果或本地索引缺失时应明确提示。
- 回测按需加载策略实际查询的证券行情，并可在一次回测中缓存已请求的数据；策略不宜在每个交易日扫描全量证券历史。

## 4. 看盘功能

### 4.1 日线 K 线

- 输入或搜索证券代码/名称，选择日期区间并加载本地日线。
- 图表展示 K 线与成交量；均线提供 MA5、MA20 两条独立开关，周期可配置。
- 支持图表拖动平移和滚轮缩放。
- 单击 K 线时显示该日日期、开盘、最高、最低、收盘和成交量等详细行情。

### 4.2 分时图

- 双击指定日线 K 线时，以该证券和日期打开分时窗口。
- 分时周期可选 1 分钟或 5 分钟；单击分时 K 线显示详细行情。
- 本地找不到所选日期分时文件时显示明确错误或空数据说明，不伪造行情。

## 5. 策略脚本管理与编辑器

### 5.1 脚本管理

- 策略脚本保存在项目 `strategies/` 目录。
- 工作区提供脚本列表，以及创建、查看、编辑、检查、保存、删除和刷新操作。
- 新建脚本时自动填入可编辑的策略框架。
- “保存并回测”操作先保存当前脚本，再以当前回测配置运行。
- 函数帮助入口读取策略 API 文档，并将 Markdown 的标题、表格、代码和列表格式化显示。

### 5.2 Python 编辑器与自动补全

- 使用 CodeMirror Python 编辑器，提供语法高亮、行号、括号匹配及清晰易辨的代码配色。
- 自动补全覆盖内置函数、`broker` 方法、方法参数、策略实例属性、当前作用域变量及 API 返回对象字段。
- 补全需按当前对象类型与作用域过滤，建议应能插入为有效 Python 代码；提示说明须准确描述其实际用途。
- 可根据 `get_history()` 查询的证券代码补全动态行情映射键；继续访问代码对应历史列表和单根记录时，提示正确的索引和行情字段。
- 支持持仓、证券信息和现金对象字段补全，包括：
  - 持仓：证券代码、持有股数、可卖股数、平均成本、市值、未实现盈亏。
  - 股票信息：代码、名称。
  - 现金：`total` 总权益、`available` 可用现金。
- 有补全建议时 Tab 接受建议；无建议时 Tab 插入两个空格，不离开编辑器焦点。换行缩进应与 Python 代码结构一致。
- 在完整表达式后输入 `.var` 可触发变量提取建议；按 Tab 或 Enter 后将表达式改写为 `变量名 = 原表达式`，默认变量名取表达式末端对象/字段，且变量名保持选中以便重命名。变量名仍选中时再次按 Tab 或 Enter 即确认该名称，并将光标移至赋值行末。
- 对象成员补全不得混入无关的全局函数、形参、其他对象成员或其他方法中的局部变量。

## 6. 策略执行与 API

### 6.1 策略入口

- 页面多标的回测脚本定义 `Strategy` 类和同步方法 `on_day(self, day, broker)`。
- `day` 是 `YYYY-MM-DD` 交易日字符串。每个交易日收盘后调用策略一次，再按所选成交模式处理委托。
- API 仍兼容带 `symbol` 参数的旧单标的回测请求及其 `on_bar` 策略。
- 执行 Python 策略的权限等同于本机应用进程权限，只允许运行用户信任的脚本。

### 6.2 股票与行情查询函数

- `get_stock_codes()`：读取本地索引中识别为沪深北普通 A 股的证券代码；不保证每个代码都有回测区间行情，退市状态过滤受本地名称索引信息限制。
- `get_stock_names(codes=None)`：按代码数组返回证券代码和名称；省略参数时返回本地股票目录中的全部证券代码和名称。
- `get_history(codes, count)`：返回各代码最近最多 `count` 条日线记录。
- 历史列表按日期从新到旧排列：`history[0]` 是最近可用行情；`history[1]` 与 `history[-1]` 表示最近一条更早的可用行情，通常但不保证是前一交易日。负索引不采用 Python 列表原生从末尾倒数语义。
- 单条日线记录包含 `date`、`日期`、`O`（开盘）、`C`（收盘）、`H`（最高）、`L`（最低）、`V`（成交量）。
- `get_history` 仅返回截至当前回测日且处于回测数据范围内的行情；停牌/缺失证券日期不会被补造。

### 6.3 账户与交易函数

- `broker.get_cash()`：返回现金信息对象，可直接作为数值参与运算；数值部分等于可用现金。`total` 为账户总权益（可用现金加已载入行情的持仓市值），`available` 为可用现金，单位均为元。
- `broker.get_equity()`：返回账户总权益。
- `broker.get_position(code)`：返回单证券持仓；`broker.get_positions()` 返回所有非零持仓映射。
- `broker.buy(code, funds)`：按金额买入指定证券；委托按 A 股 100 股整数手处理。
- `broker.sell(code, funds=None)`：按金额卖出指定证券；省略金额时卖出全部可卖持仓。
- `broker.cancel_all()`：撤销所有尚未成交委托。
- 旧单标的 API 继续提供 `order_value`、`order_target_value`、`order_target_percent` 等目标仓位委托。
- `sma`、`ema`、`cross_up`、`cross_down` 用于常用均线及交叉信号计算。
- 序列版上穿条件为上一时点 `fast <= slow` 且当前 `fast > slow`；下穿条件为上一时点 `fast >= slow` 且当前 `fast < slow`。数值版只比较当前大小，不代表刚发生穿越。

## 7. 回测配置、交易规则与结果

### 7.1 配置项

- 策略文件、回测开始/结束日期、初始资金、成交模式。
- 可配置佣金率、印花税率、滑点比例和最低佣金。
- 默认初始资金为 100,000 元；金额输入支持整数。
- 页面多标的回测不要求用户预先指定单一证券；策略自行选择证券池与交易对象。

### 7.2 撮合与限制

- 推荐模式为下一交易日开盘价撮合；回测最后一天提交的订单可能因区间结束而不成交。
- 当日收盘价撮合使用当日收盘数据，存在前视风险，应提示用户谨慎使用。
- 买入及部分卖出按 100 股整数手；现金不足时买入数量可按整手减少。
- 佣金、最低佣金、印花税和滑点计入实际交易结果；遵循 A 股 T+1。
- 不模拟涨跌停、停牌撮合、分红及拆并股；缺失行情不可当作有效成交。
- 多标的账户按已加载的最新收盘价估值；策略应先查询持仓所需行情，避免未加载持仓被错误估值。

### 7.3 回测报告与持久化

- 回测结果展示绩效指标、净值曲线和逐笔成交明细。绩效包含总收益、年化收益、最大回撤、夏普、胜率、交易次数，以及盈利因子、单笔盈亏统计、连胜连亏和平均仓位等指标。
- 每次运行将策略源码、回测参数、绩效、净值序列和成交明细保存在一个 `backtest_results/*.json` 文件中，确保历史脚本修改后仍可查看当时源码。
- 结果包含回测元信息、策略源码、绩效汇总、每日净值/权益曲线和成交列表；多标的成交记录应包含证券代码及可用名称。
- 历史回测列表按时间倒序展示策略、标的、区间、收益和回撤；支持查看详情和删除记录。
- 详情页分为绩效与净值、策略代码、成交明细；成交明细支持 CSV 导出。
- 净值图展示买入/卖出信号，支持缩放；双击日期可查看对应成交。
- 后端持久化失败时，应向界面明确显示错误，同时保留可返回的本次内存回测结果。

## 8. 后端接口清单

| 接口 | 方法 | 功能 |
|---|---|---|
| `/api/config` | GET / POST | 读取、保存和验证本地数据目录配置 |
| `/api/strategies` | GET / POST | 列出、创建策略脚本 |
| `/api/strategies/help` | GET | 获取 Markdown 格式的策略函数说明 |
| `/api/strategies/{filename}` | GET / PUT / DELETE | 读取、更新、删除策略脚本 |
| `/api/strategies/validate` | POST | 检查策略语法及入口 |
| `/api/stocks/search?q=...` | GET | 按证券代码、名称或拼音首字母搜索 |
| `/api/kline` | GET | 读取指定证券日线数据 |
| `/api/kline/intraday` | GET | 读取指定日期的 1/5 分钟分时数据 |
| `/api/backtest/run` | POST | 执行回测并尝试保存结果 |
| `/api/backtest/list` | GET | 获取历史回测摘要 |
| `/api/backtest/detail?id=...` | GET | 获取单次回测完整结果 |
| `/api/backtest/delete?id=...` | DELETE | 删除指定回测结果 |

## 9. 技术约束与安全

- 后端使用 Python 与 FastAPI；行情读取基于 mootdx 和本地通达信文件。
- 前端为本地单页应用；编辑器和图表资源随项目提供。修改前端源文件后需重新构建静态 bundle。
- 配置使用本地 `config.json`，回测结果使用标准 JSON 文件；不以数据库、Redis 或消息队列作为运行依赖。
- Python 策略在后端本机进程中执行，不构成隔离沙箱。默认只供本机个人使用，不要将服务暴露到公网。
- 回测文件会随运行次数增长；可通过历史记录删除或手动清理 `backtest_results/`。
