# 本地交易回测与看盘系统 — 项目规范

## 1. 项目目标

本项目面向个人投资研究，提供基于本地通达信数据的行情查看、Python 策略编辑与历史回测能力。产品优先保证本地可用、行为可解释、策略提示准确和回测结果可复查，不以实盘交易或多人协作为目标。

## 2. 产品与运行约束

- 应用以单用户、本机运行方式提供。行情来自用户配置的通达信数据目录，不依赖外部行情服务。
- 本地证券名单按 `.tnf` 所属市场和代码段筛选沪深北普通 A 股；排除 B 股、指数、基金、债券等非普通股。退市识别依赖名称标记，只能尽力排除。
- 配置保存于项目根目录 `config.json`；回测结果以独立 JSON 文件保存在 `backtest_results/`。
- 不引入数据库、Redis、消息队列或后台任务服务作为运行前提。前端静态资源随项目提供已构建 bundle。
- 页面以中文为主，回测、看盘和设置通过统一顶部导航切换。顶部区域提供固定/取消固定操作。
- 日期默认值使用本机日期：结束日为今天，开始日为一年前；回测与看盘保持一致。
- 对数据缺失、无效参数、脚本错误及持久化错误应明确反馈，不以成功状态掩盖失败。

## 3. 策略与交易语义

- 页面多标的策略入口为 `Strategy.on_day(self, day, broker)`；`day` 为 `YYYY-MM-DD` 交易日，回调在当日收盘后执行。
- 推荐使用下一交易日开盘价撮合。当日收盘价撮合属于可能产生前视偏差的模式，界面和文档应明确提示。
- A 股买入和部分卖出按 100 股整数手处理，并计入佣金、最低佣金、印花税和滑点；遵循 T+1，当日买入股票不可当日卖出。
- 回测历史按交易记录中的实际成交结果统计。缺失行情、停牌及区间末尾未成交委托不得伪装成已成交。
- `broker.get_cash()` 返回可参与数值运算的现金信息对象：`total` 表示账户总权益（可用现金加已载入行情的持仓市值），`available` 表示可用现金；字段单位为元。须保留原有 `broker.get_cash() * 比例` 用法兼容。
- 历史行情按日期从新到旧排列：`history[0]` 是最近一条可用行情；`history[1]` 与 `history[-1]` 都表示最近一条更早的可用行情。停牌或缺失数据时，它不保证是自然日意义上的昨天。
- 序列输入的 `cross_up` 判断上一时点 `fast <= slow` 且当前 `fast > slow`；`cross_down` 判断上一时点 `fast >= slow` 且当前 `fast < slow`。

## 4. 编辑器与代码提示规范

- 策略编辑器使用 Python 语法高亮和自动补全；关键字、字符串、数字、注释和提示弹窗需保持清晰的前景/背景对比度。
- 补全只显示当前作用域及当前对象类型相关的有效建议。对象成员访问（如 `history.`、`position.`、`cash.`）不得混入不相关的全局函数、形参或其他作用域变量。
- 对象类型应根据表达式与实际返回结构推断；涵盖行情映射、历史列表、单根行情、持仓、证券信息、账户现金、列表/字典/集合等常用对象。
- 当代码能确定动态证券代码时，历史映射成员建议应体现这些代码；继续索引历史记录时，应依次提示正确的行情字段。
- 提示说明必须描述真实用途和字段含义，避免“持仓字段”“当前对象可用成员”等空泛文案。
- 有补全候选时，Tab 接受当前建议；无候选时，Tab 在光标处插入两个空格且不使编辑器失去焦点。换行自动缩进应遵循 Python 代码结构。
- 在表达式末尾输入 `.var` 时，提供变量提取补全；接受后生成 `变量名 = 原表达式`，默认名取表达式末端对象/字段，并选中变量名便于立即重命名。Tab 或 Enter 均可接受；变量名仍选中时再次按 Tab 或 Enter 确认名称，并将光标移至该行末。
- 新建策略时提供可直接检查和运行的 `Strategy` 框架模板。

## 5. 图表与交互规范

- 日线 K 线至少展示开、高、低、收、成交量；单击 K 线显示该日详细行情，双击 K 线打开该交易日的分时窗口。
- 分时窗口支持 1 分钟和 5 分钟周期；无本地分时数据时给出明确提示。
- 日线图支持拖动平移、滚轮缩放，并提供 MA5、MA20 的独立显示开关及可配置周期。
- 回测净值曲线应清晰呈现回测日期及买卖成交信号；缩放查看时仍可追踪日期，双击日期可查看对应成交。
- 股票搜索候选不得遮挡输入框，候选中同时显示证券代码和名称。

## 6. 文档与变更要求

- 用户可见行为、内置 API、返回字段或交易语义有变化时，必须同步更新 `文档\需求.md` 和相关策略函数说明。
- `文档\项目规范.md` 记录跨功能长期有效的产品约束；详细功能清单、接口及限制以 `文档\需求.md` 为准。
- 后端行为以实现和自动化测试为准，前端提示与文档必须和真实行为一致，不提供无法使用或语义误导的代码建议。
- 修改后使用项目已有测试、Python 语法检查和前端构建进行相关验证；保留与本次变更无关的既有行为。
